# Objet — паспорта объектов с QR-кодами

Система для бренда декоративных дизайнерских объектов: **панель генерации страниц** + **страница-паспорт**
для каждого физического экземпляра. К объекту прилагается печатный паспорт с QR-кодом, QR ведёт на
сгенерированную страницу с фотографией, названием, коллекцией и номером в серии.

Дизайн — швейцарская типографика: Helvetica, сетка, тонкие линейки, один акцентный цвет.
Стек: Next.js 15 (App Router) + TypeScript + Tailwind + SQLite (better-sqlite3) + qrcode. Всё работает
локально, данные лежат в `./data` (база + загруженные фото), внешние сервисы не нужны.

---

## 0. Запуск в один клик (для себя, на своём компьютере)

Нужен только установленный [Node.js LTS](https://nodejs.org) (один раз). Дальше — двойной клик по файлу
в этой папке:

| Система | Файл |
| --- | --- |
| Windows | `ЗАПУСТИТЬ-САЙТ.bat` |
| macOS | `ЗАПУСТИТЬ-САЙТ.command` |
| Linux | `ЗАПУСТИТЬ-САЙТ.sh` (или значок `objet.desktop`) |

Что делает запускалка (`scripts/launch.mjs`):

1. при первом запуске создаёт `.env.local` и **генерирует пароль администратора** (печатает его в окне);
2. если нет `node_modules` — ставит зависимости (первый запуск, ~1–2 минуты, нужен интернет);
3. если нет сборки — собирает сайт (~30 секунд), дальше запуск за 2–3 секунды;
4. берёт свободный порт (если 3000 занят — уйдёт на 3001 и напишет адрес), поднимает сайт и открывает браузер;
5. если сайт уже запущен — второй раз его не поднимает, просто открывает браузер.

Остановить сайт: закрыть окно с логами или `Ctrl+C`. Краткая инструкция для не-технического пользователя —
в файле `КАК-ЗАПУСТИТЬ.txt`.

```bash
node scripts/launch.mjs --dev          # режим разработки с горячей перезагрузкой
node scripts/launch.mjs --port=4000    # другой порт
node scripts/launch.mjs --seed         # добавить демо-данные при первом запуске
node scripts/launch.mjs --no-open      # не открывать браузер
```

## 1. Быстрый старт локально (вручную)

```bash
npm install
cp .env.example .env.local      # и поменяйте пароль/секрет
npm run seed                    # (необязательно) демо-данные: 3 коллекции, 5 объектов, 17 страниц
npm run dev                     # http://localhost:3000
```

Для продакшен-режима локально:

```bash
npm run build && npm start      # http://localhost:3000
```

Куда идти:

| Адрес | Что это |
| --- | --- |
| `/admin` | панель: обзор, объекты, коллекции, страницы, настройки |
| `/admin/login` | вход по паролю (`ADMIN_PASSWORD`) |
| `/o/<КОД>` | сгенерированная страница объекта (то, что открывает QR) |
| `/print/<id>` | печатный паспорт формата A6 с QR |
| `/media/<файл>` | отдача загруженных фотографий |

### Переменные окружения (`.env.local`)

| Переменная | Значение |
| --- | --- |
| `ADMIN_PASSWORD` | пароль входа в панель (обязательно поменяйте) |
| `SESSION_SECRET` | длинная случайная строка для подписи cookie сессии |
| `BASE_URL` | публичный адрес сайта — **именно он зашивается в QR-коды** (`http://localhost:3000` локально) |
| `DATA_DIR` | где хранить базу и фото (по умолчанию `./data`) |
| `BRAND_NAME` | название бренда по умолчанию (дальше меняется в Настройках) |
| `INSECURE_COOKIES` | `1` — если продакшен-сборка крутится по http без TLS (например, по IP VPS) |

## 2. Модель данных и логика серийности

```
Коллекция (название, дата релиза, обложка, описание)
   └── Объект (название, фото, тип, материал, размеры, год, лимитированность)
          └── Страница  =  один физический экземпляр  =  один QR-код на паспорте
```

* **Код страницы** — 8 символов из алфавита без похожих знаков (`ABCDEFGHJKMNPQRSTUVWXYZ23456789`),
  чтобы код было удобно читать и печатать. Ссылка короткая: `/o/GPE3UHGK`.
* **Номер (серийность)** присваивается автоматически по порядку внутри объекта: 1, 2, 3 …
  Удаление страницы не перенумеровывает остальные — номер экземпляра не переиспользуется.
  Можно задать номер вручную (например, чтобы начать с 7).
* **Лимитированный объект**: в настройках объекта включается «Лимитированный тираж» и указывается
  тираж (например, 100). На странице это отображается как `03 / 100`, плюс метка «Лимитированная серия».
  Номера вне тиража система не даст создать.
* **Открытая серия**: знаменатель на странице — **количество созданных страниц** объекта
  (`03 / 12`), то есть ровно то число, которое вы видите в панели. Галочка «Показывать общее число
  страниц» отключает знаменатель — тогда на странице будет `№ 03`.
* **Статус страницы** `active` / `void`: аннулированная страница открывается, но показывает
  «Страница аннулирована» (например, объект утерян или перепродан).

## 3. Как работать в панели

1. **Коллекции** → «Новая коллекция»: название, дата релиза, описание, обложка.
   Список коллекций и объектов всегда сортируется по дате релиза, есть поиск и фильтр.
2. **Объекты** → «Новый объект»: название, коллекция, тип (ваза/лампа/…), материал, размеры, год,
   описание, статус, лимитированность.
3. Во вкладке **Фотографии** перетащите файлы (или выберите вручную). Картинки уменьшаются в браузере
   до 2000 px и сохраняются в WEBP, первая фотография — главная, порядок меняется стрелками.
4. Во вкладке **Страницы** нажмите «+ Добавить страницу» — можно сразу указать количество (до 50),
   номер (опционально) и метку (например, «шоурум»). Здесь же счётчик «Создано страниц» — это число
   и показывается на сгенерированной странице как знаменатель.
5. Кнопка **QR-код** у страницы: превью, скачивание PNG/SVG, копирование ссылки, переход на страницу
   и **Печать паспорта** (A6, 105 × 148 мм — печатать при масштабе 100%, без полей).
6. **Настройки**: название бренда, слоган, заголовок паспорта, контакт, подпись в подвале,
   акцентный цвет, язык страниц (RU/EN) и адрес для QR-кодов.

> **Важно про QR и домен.** QR кодирует `BASE_URL` (или адрес из «Настроек», он приоритетнее).
> Пока работаем локально — это `http://localhost:3000`. После переезда на VPS поменяйте адрес
> в Настройках и **перегенерируйте QR-коды для уже напечатанных паспортов** (старые коды будут вести
> на localhost).

## 4. Структура проекта

```
src/
  app/
    page.tsx                 # публичная главная: коллекции и последние страницы
    o/[code]/page.tsx        # СГЕНЕРИРОВАННАЯ страница объекта (то, что открывает QR)
    o/[code]/not-found.tsx   # 404 в том же стиле
    print/[id]/page.tsx      # печатный паспорт A6 (собственный print.css)
    admin/                   # панель: layout с сайдбаром + login, обзор, products, collections, pages, settings
    api/                     # REST: auth, admin/collections|products|pages|media|upload|settings, media/*
  components/admin/          # UI панели: таблицы, формы, менеджер фото, менеджер страниц, QR-диалог
  lib/
    db.ts + schema.sql       # SQLite: схема (единый источник правды)
    repo.ts                  # весь доступ к данным и бизнес-логика (серийность, тираж, slug, коды)
    qr.ts                    # сборка QR (PNG/SVG/DataURL) и публичных ссылок
    storage.ts               # загрузка/удаление фото, чистка «осиротевших» файлов
    auth.ts, middleware.ts   # пароль, подписанная cookie, защита /admin, /api/admin, /print
    types.ts, i18n.ts, color.ts, ids.ts, settings.ts
scripts/
  seed.mjs                   # демо-данные
  smoke.mjs                  # сквозной e2e-тест (53 проверки)
deploy/
  objet.service, nginx.conf.example   # заготовки для VPS
```

## 5. Демо-данные и проверки

```bash
npm run seed     # добавит 3 коллекции, 5 объектов, 17 страниц (только если база пустая)
npm run typecheck
npm run build
npm run smoke    # поднимает прод-сборку на порту 3311 в ./data-smoke и проходит весь сценарий
```

`npm run smoke` проверяет вход и защиту API, создание коллекций/объектов, автоматическую нумерацию,
запрет номера вне тиража и дублей, содержимое публичной страницы (`01 / 100`, коллекция, материал),
валидность PNG/SVG QR и адрес в QR, загрузку и отдачу фото, печать паспорта, поиск/сортировку,
перенастройку бренда и домена, удаление страниц и объектов.

## 6. Перенос на VPS (продакшен)

Пошагово, когда локально всё устраивает:

1. **Сервер**: Ubuntu 22.04/24.04, Node.js 22 LTS, `npm ci`, nginx.
2. **Код**: `git clone` в `/var/www/objet` (или rsync), создать `.env.local` на сервере:
   `ADMIN_PASSWORD=<свой>`, `SESSION_SECRET=<openssl rand -base64 48>`, `BASE_URL=https://passport.example.com`.
3. **Сборка**: `npm ci && npm run build`.
4. **Служба**: скопировать `deploy/objet.service` → `/etc/systemd/system/objet.service`,
   `systemctl daemon-reload && systemctl enable --now objet` (либо pm2: `pm2 start npm --name objet -- start`).
5. **Nginx**: `deploy/nginx.conf.example` → `/etc/nginx/sites-available/objet`, симлинк в `sites-enabled`,
   `nginx -t && systemctl reload nginx`.
6. **HTTPS**: `certbot --nginx -d passport.example.com`. После этого адрес `https://…` уходит в QR-коды
   (cookie сессии становится Secure автоматически, потому что `BASE_URL` начинается с `https`).
7. **Данные**: `./data` (SQLite + фото) — единственное, что нужно бэкапить:
   `tar czf objet-$(date +%F).tar.gz data/` по крону. Перенос — просто скопировать папку `data/`.
8. **Перегенерировать QR** для напечатанных паспортов, если адрес менялся (кнопка «QR-код» → «Скачать PNG»).

Если HTTPS пока нет и сайт открывается по IP, добавьте `INSECURE_COOKIES=1`, иначе браузер не сохранит cookie входа.

## 7. Что можно добавить дальше

* Публичный каталог объектов по коллекциям (сейчас главная — витрина-превью).
* Мультиязычные страницы одновременно (RU + EN в одном паспорте).
* Экспорт листа QR-меток на печать (A4, много паспортов сразу).
* Регистрация владельца на странице объекта («зарегистрировать изделие»), передача/перепродажа.
* Несколько администраторов и роли вместо одного пароля.
* Загрузка фото в S3-совместимое хранилище, если объектов станет очень много.

## 8. Полезные мелочи

* Страница объекта рендерится на сервере (`force-dynamic`), поэтому смена названия/фото/статуса
  сразу видна по тому же QR — перегенерировать страницу не нужно.
* Отдаваемые фото кешируются «навсегда» (уникальные имена файлов), сами файлы — в `data/uploads`.
* Удаление объекта удаляет его страницы; удаление коллекции объекты сохраняет (снимает привязку).
* Осиротевшие фото можно чистить: `collectOrphans()` в `src/lib/storage.ts`.
* Журнал действий (`audit_log`) виден на странице «Обзор».
